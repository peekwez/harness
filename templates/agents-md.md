# AGENTS.md — this repo is harness-enforced

Any coding agent working in this repo (Claude Code, or anything that can
shell out) operates under the harness substrate. Read this before editing.

## The rules that bind you

1. **Provenance.** Every artifact is authored (human judgment — ADRs,
   contracts, config, decisions) or derived (regenerated by hooks —
   `.harness/shadows/**`, `edges.jsonl`, `boundaries.jsonl`, telemetry).
   Never hand-edit a derived file; CI proves they regenerate identically.
2. **Work in slices.** All implementation happens inside a declared slice
   from `.harness/backlog.jsonl`: bind it first, honor `declares_dep` and
   `predicted_files`, amend declarations before touching anything else.
3. **Lookup, never interpret.** Recurring choices are decision rows in
   `.harness/decisions.jsonl`. If a row answers your question, obey it. If
   no row exists and the question will recur, park it for adjudication —
   don't improvise.
4. **Shadows over source.** Need another module's interface? Load its shadow
   from `.harness/shadows/`, never paste its source.
5. **Log abandoned attempts.** Before switching approach:
   `harness memory write --slice <id> --kind attempt ...` — the next session
   only knows what substrate knows.

## Autonomy contract

A bound slice is yours to finish: implement → acceptance green → self-review
→ fix findings → close-slice, with no human in the loop. Stop only for:
a parked (uncertain) review finding, an author-gate gap, or a gate that
still blocks after 3 honest fix attempts. Gate blocks name their own fix —
apply it, don't ask. Closing a slice releases its binding; bind the next
slice or run `harness slice --release` before Phase-0 edits.

## Workflow (in order)

```
harness doctor                     # engine deps preflight
init -> architect -> author-gate   # Phase 0: substrate authored, human signs
backlog                            # spec -> dependency-ordered slices
slice/resolve -> build -> review -> close-slice   # per-slice loop
status / adjudicate                # telemetry + dispute resolution
verify                             # CI: derived artifacts regenerate
```

In Claude Code these are `/harness:init`, `/harness:architect`,
`/harness:backlog`, `/harness:build <slice>`, `/harness:review <slice>`,
`/harness:close-slice <slice>`, `/harness:status`, `/harness:adjudicate`
(user-invoked). Other frameworks call `bin/harness` from the plugin install
directly — the engine is framework-agnostic.

## Gates you will meet

G1 manifests · G2 context-loaded (load the slice context before editing) ·
G3 spec-bound (stay inside declarations) · G4 shadow freshness ·
G5 uses ⊆ declares + no reimplementation · G6 interface drift needs an ack ·
G7 derived artifacts regenerate byte-identically · G8 unenforced surface is
enumerated. Every block names its rule; the fix is in the finding.
