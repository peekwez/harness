## Shared interfaces

Plans must use these names exactly.

### Upgrade step framework (W1 creates; all plans register steps)

File: `engine/upgrade_010.py`.

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Callable

Ask = Callable[[str], bool]          # returns True when the human accepts

@dataclass(frozen=True)
class Step:
    id: str                                   # "w1.untrack-shadows"
    title: str                                # one STE-80 line for the plan
    describe: Callable[[Path], list[str]]     # pending changes; [] = nothing to do
    apply: Callable[[Path, Ask], list[str]]   # performs them; returns report lines
    destructive: bool = False                 # True -> apply must call ask() first
    advise: Callable[[Path], list[str]] | None = None  # "check: ..." lines; never pending

STEPS: list[Step] = []

def register(step: Step) -> Step: ...
def plan(root: Path) -> list[dict]: ...       # [{"id", "title", "changes": [...]}] for steps with changes
def run(root: Path, ask: Ask, *, dry_run: bool) -> list[dict]: ...  # rows: {"id","title","changes","report"?}
def advice(root: Path) -> list[dict]: ...    # [{"id", "check"}] from every step's advise
```

- A step must be idempotent: after `apply`, `describe` returns `[]`.
- Each plan registers its steps in its own module, `engine/upgrade_w<N>.py`, with `register(...)`. `engine/upgrade_010.py` imports those modules at the bottom in workstream order.
- A file that harness must not edit (no harness marker) is never a pending change. The step reports it through `advise` as a `check:` line. This keeps a second run clean.
- Upgrade never promotes memory and never stages or commits. It prints the commit command.
- Report keys: `"steps"` (run rows), `"advice"` (step advice), `"checks"` (W8: doctor and verify results), `"human_checks"` (W8: everything a human must do).
- `upgrade_project` calls `upgrade_010.run(...)` after the schema migration. `SCHEMA_VERSION` becomes 2. `MIGRATIONS[1]` only stamps the version; the steps do the work.
- W1 adds `--yes` (ask always returns True). Without `--yes`, `ask` prompts on stdin; with no TTY it returns False and the step reports "skipped: needs confirmation".

### Context (W1)

- `engine/resolver.py`: `MAX_INJECTION_CHARS = 9000`. `resolve(root, slice_id, config) -> {"blocks": [{"key", "priority", "text"}], "injections": [...], "cut": [...], "chars": int}`.

### Telemetry (W2)

- `engine/telemetry.py`: `emit(root, kind, meta)` appends to `.harness/cache/events.jsonl` (gitignored). `record_slice_summary(root, slice_id, extra: dict | None = None) -> dict` writes one row to `.harness/slice-metrics.jsonl` at close. Other plans add fields through `extra`: W5 adds `{"red_before_green": bool, "green_at_start": bool}`, W6 adds `{"explore_skipped": "<reason>"}` through the working document, read at close.

### Gates (W2)

- `engine/gates/__init__.py`: `exempt(rel: str, config) -> bool` reads `gates.exempt_paths`. Default list: `[".harness/", "adr/", ".github/", "tests/", "docs/", ".claude/", "explore/"]`.

### Findings (W4)

- `engine/events.py`: `make_finding(code, rule_ref, message, severity="advisory", layer=..., inject=..., precedents=..., key=None, fix=None)`. The default severity stays `"advisory"`, as in 0.9.4. Plans W1–W3 may pass `fix=` only after W4 lands; until then they put the fix command at the end of `message`. W4 moves it.
- `engine/findings.py`: `CATALOG: dict[str, str]` maps finding code to explanation. Each plan that adds a finding code adds a catalog entry once W4 exists. W5 and W6 add entries directly.

### Text lint (W4)

- `engine/lint_text.py`: `lint_paths(paths: list[Path], glossary: Path | None) -> list[dict]` with `{"path", "line", "rule", "text"}`. CLI: `harness lint-text <paths>`.

## Rules for every plan

1. Follow `superpowers:writing-plans`: the header, Global Constraints, Review Focus, and tasks with real code and real test code. No placeholders.
2. Use TDD. Tests use `tests/conftest.py` (`build_toy_repo`, `run_cli`, `git`). Run with `python3 -m pytest tests/ -q`.
3. Delete the tests of removed features in the same task that removes the feature.
4. Every change to consumer-visible substrate has an upgrade step in the same plan.
5. Finding messages and CLI output follow STE-80: rule, what is wrong, file; 25 words or fewer; then the fix.
6. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
7. The last task of each plan: `make test` is green, then open a PR into `release/0.10` that closes the plan's issue.
