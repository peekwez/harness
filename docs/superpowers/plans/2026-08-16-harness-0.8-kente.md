# harness 0.8 — kente-capable + superpowers-composable — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship harness 0.8.0 so the kente monorepo (PEP 420 namespace packages, uv workspace, PR-protected `main`, superpowers installed) can be built under harness enforcement.

**Architecture:** Every change is an opt-in `config.yaml` key or a skill/template edit; absent config = 0.7.1 behaviour. Engine stays framework-agnostic; policy lives in `engine/`, adapters translate. One PR per task, each referencing its Linear issue (`GOO-NN`) in branch name, commit message and PR body.

**Tech Stack:** Python 3.10+ stdlib + pyyaml + tree-sitter; pytest (307 tests, `make test`); `bin/harness verify` (`make verify`).

**Spec:** `adr/002-kente-capable-superpowers-composable.md` (decision rows D-007…D-015). Linear umbrella GOO-72.

## Global Constraints

- Backward compatible: all 307 existing tests stay green unchanged unless the ADR changes the behaviour they assert (say so in the PR).
- Every new blocking finding cites a `rule_ref` (`adr:002` unless a gate id fits) — the engine rejects rule-ref-less blocks (D-003).
- New modules ≤ 500 lines; Google-style docstrings on public functions.
- Fail closed, fail loud: load errors and misconfig become named findings, never silent skips (D-001).
- README must list every CLI subcommand (test enforces); `docs/SPEC.md` must define every `§/C/T/M` marker a skill cites (test enforces).
- Branch `goo-NN-<slug>` from `main`; commit messages end with `(GOO-NN)`; PR body: `Linear: GOO-NN` line + `https://linear.app/goodwork-ai/issue/GOO-NN`. Run `make test` and `make verify` before every push.
- Work in a worktree: `git worktree add <scratch>/goo-NN -b goo-NN-<slug> main` (the harness repo's own hooks fire there — G3/G2 findings are advisory; do not edit `.harness/` derived files by hand).
